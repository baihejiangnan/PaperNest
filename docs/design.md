# 全局 UI 规范：Obsidian 配色与 HeroUI 语义

PaperNest 以阅读内容为视觉中心，保留轻量编辑入口。本文件是应用框架、编辑器、弹窗与新增组件的统一 UI 规范。当前技术栈为原生 TypeScript/CSS；没有安装 React、Tailwind 或 HeroUI。采用 HeroUI v3 的语义变量约定，以便后续组件接入；不要将本文视为已迁移到 HeroUI 的说明。

## 色彩与主题

运行时颜色的唯一入口是 [src/ui-theme.css](../src/ui-theme.css)。布局及组件样式在 [src/styles.css](../src/styles.css)。[src/miku-cream.ts](../src/miku-cream.ts) 保留历史文件名，负责 Crepe 结构样式与共享语法高亮；实际颜色使用全局变量。

| 用途 / 变量 | 浅色 | 深色 | 使用范围 |
| --- | --- | --- | --- |
| 主背景 `--background` / `--bg` | #ffffff | #1c1c1c | 文档与页面 |
| 正文 `--foreground` / `--fg` | #222222 | #dadada | 标题、正文、普通操作 |
| 浮层 `--surface` | #ffffff | #282828 | 弹窗、菜单 |
| 次级背景 `--surface-secondary` / `--bar-bg` | #f6f6f6 | #232323 | 工具栏、侧栏、代码隔行 |
| 悬停 `--surface-tertiary` / `--hover` | #efefef | #333333 | 中性控件反馈 |
| 次要文字 `--muted` / `--bar-fg` | #5c5c5c | #b3b3b3 | 路径、提示、辅助信息 |
| 边框 `--border` | #e4e4e4 | #3f3f3f | 分区、输入框、浮层 |
| 强调 `--accent` | #8a5cf5 | #8a5cf5 | 主要操作、焦点、选中状态 |
| 危险 `--danger` | #d92d45 | #fb464c | 删除、放弃更改；按钮文字使用 `--danger-foreground` |

颜色基础参考 [Obsidian 官方配色变量](https://docs.obsidian.md/Reference/CSS%20variables/Foundations/Colors)，组件语义参考 [HeroUI v3 主题文档](https://heroui.com/en/docs/react/getting-started/theming)。警告、成功和语法高亮属于状态色，不能作为第二套应用强调色。

- `color_scheme` 默认为 `system`；可在设置中选择 `light` / `dark`。系统主题变化立即更新，手动选择优先。初始化前使用 CSS 媒体查询避免深色系统出现浅色闪屏。
- `accent` 仍允许用户覆盖。选中背景、链接、焦点及按钮从此变量派生；不得硬编码初音绿色。
- 旧配置缺少 `color_scheme` 时，原默认 `#39C5BB` 迁移为紫色，原代码隔行色 `#FAFFFF` 迁移为跟随主题。其他自定义颜色保留；新配置中主动选择绿色仍有效。
- `code_alternate_row_color = ""` 表示使用主题次级背景；用户可选择自定义颜色或通过“默认”恢复自动配色。
- Markdown 与普通文本 Code 模式共用语义高亮和用户字体设置。HTML/PDF 导出使用中性浅色与紫色，以适合独立阅读及打印。

## HeroUI 全局适配约定

以下变量在 `ui-theme.css` 中已定义，现有原生控件与未来 HeroUI v3 组件共享它们。接入 HeroUI 时需遵循对应版本的 CSS 导入及层顺序，不能直接安装组件后依赖其默认蓝色或默认主题。

| HeroUI v3 语义变量 | 本项目规则 |
| --- | --- |
| `--background`、`--foreground` | 页面背景与文字；原生应用使用别名 `--bg` / `--fg` |
| `--surface`、`--surface-foreground`、`--surface-hover` | 卡片、弹窗及菜单层 |
| `--accent`、`--accent-foreground`、`--accent-soft`、`--accent-soft-foreground` | 主按钮、柔和选中状态及其文字 |
| `--field-background`、`--field-foreground`、`--field-border`、`--field-placeholder`、`--field-hover`、`--field-focus` | 所有输入控件 |
| `--focus`、`--separator`、`--muted` | 键盘焦点、分隔线、辅助文字 |
| `--danger`、`--danger-foreground`、`--success`、`--warning` | 按操作语义使用；危险按钮必须有文字名称 |

若未来采用 HeroUI v2，其 Tailwind 插件颜色如 `primary`、`content1` 需要单独映射到这些全局变量；不得把 v2 的 `--heroui-*` 格式与 v3 CSS 变量混用。当前未引入任何 HeroUI 包或 Tailwind 配置。

## 尺寸与交互基础

- 文件树的 MD 筛选放在导航栏搜索图标下方，默认启用，用强调色和 `aria-pressed` 表达状态；提示明确说明只显示 Markdown 文档（`.md`、`.markdown`、`.mdx`）及包含它们的文件夹，常规设置提供同一开关。没有匹配项时区分于普通空目录。
- 侧栏分隔线提供 8 px 命中区域，不额外占用布局宽度；悬停、拖动和键盘焦点使用强调色。侧栏宽度为 160–600 px，并至少为正文保留 240 px（原生最小窗口范围内）；窗口缩放不覆盖用户保存的偏好。双击恢复响应式默认值，键盘支持左右方向键、Shift 加速和 Home／End。

- 间距使用 4 / 8 / 12 / 16 / 24 px 级别。UI 默认使用系统无衬线字体；文字层级为弹窗标题 20–22 px、设置标题 18 px、正文 14 px、辅助说明 12 px。编辑器字体独立由用户设置控制。
- 控件默认高度 32 px；输入框和按钮圆角 6 px、菜单 8 px、弹窗 12 px。外框与内部控件必须有层级区分。
- 普通按钮使用中性色；主操作使用紫色；删除及放弃修改使用红色。禁用按钮降低透明度且禁止提交。
- `:focus-visible` 使用 2 px 强调色轮廓与 2 px 外扩；不能只用颜色细微变化表达键盘焦点。交互过渡为 140 ms；尊重 `prefers-reduced-motion`。
- 层级使用 `--z-popup: 220`、`--z-modal: 230`、`--z-modal-nested: 240`、`--z-preview: 250`；新浮层不能任意叠加更高数字。

## 弹窗规范

### Windows 右键“新建 MD 文件”

系统“新建 → MD 文件”通过 Shell 创建空 `.md` 文档，应用关闭时也可使用。应用内文件树已有独立的“新建文件”入口。

- 设置位置：**文件关联 → Windows 资源管理器 → 在右键“新建”中显示 MD 文件**，`windows_new_md` 默认关闭。非 Windows 隐藏；控件显示真实注册状态、处理中和失败原因。开关独立于 MD 文件树筛选与“打开方式”。
- 注册范围为 `HKCU\Software\Classes\.md\ShellNew`，使用 `NullFile` 创建空文件；`MenuText` 和 `ItemName` 引用 EXE 中的本地化字符串资源，以显示菜单名称与默认文件名。实现依据为 Microsoft 的 [New 子菜单说明](https://learn.microsoft.com/en-us/windows/win32/shell/context#extending-the-new-submenu) 与 [文件类型说明](https://learn.microsoft.com/en-us/windows/win32/shell/fa-file-types)。资源文本变化时须更新间接引用的版本修饰符，避免 [MUI 字符串缓存](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/nf-shlwapi-shloadindirectstring) 保留旧文字。
- 启用前检查合并后的 `.md` 类型及根级／嵌套 `ShellNew`；已有第三方新建项时保留并禁用开关。现有类型没有打开命令时提示先在 Windows 中修复。仅在 `.md` 类型缺失时补充专用 `PaperNest.NewMarkdown` 类型；不覆盖现有默认类型或 `UserChoice`。
- Rust 后台命令负责注册、读回与保存设置；失败回滚。当前用户的独占锁串行化跨进程操作，写前日志记录本功能创建的键及修改前后值。关闭时仅还原仍与本功能写入值一致的项目，只删除空的自建键；保留其他软件后来写入的数据。
- 设置打开、窗口返回焦点及跨窗口事件刷新真实状态；手动修改设置即时应用。普通设置保存读取实际注册状态，避免旧窗口保存字体或会话时撤销系统功能。另一安装目录仍拥有注册时须在该目录关闭；同目录更新或原程序已不存在时可重新绑定资源路径。
- MSI 最终卸载调用同一清理入口，清理失败不阻止卸载；重大版本升级期间跳过该清理，待新程序启动后刷新资源路径。便携版删除前先关闭开关。操作后通知 Shell 刷新，不重启 Explorer。
- Windows 实测范围与剩余平台／安装生命周期检查见 [开发说明](development.md#windows-系统新建-md-文件2026-10-08) 和 [TODO](../TODO.md)。

### 正文右键菜单

- 正文、源码和代码块使用应用内菜单；按编辑位置提供可用操作，正文包含“文本格式”“段落设置”“插入”分支，纯文本位置不显示富文本操作。
- 菜单使用 `--surface`、`--fg`、`--muted`、`--border` 与 `--shadow-popup`，行高至少 32 px，左侧线性图标、右侧快捷键／状态勾选／分支箭头。悬停使用中性 `--hover`，键盘导航保留紫色焦点边框。
- 主菜单与子菜单作为独立浮层挂在 body；靠近屏幕右缘时子菜单向左展开，低窗口内菜单可滚动。父菜单滚动时收起子菜单，避免分支脱离触发行。
- 菜单操作保留文本选区；方向键、Home/End、Enter/Space、Esc/Tab 与 Shift+F10 可用。点击外部、滚动正文、调整窗口或切换文档会关闭菜单。菜单不遮罩正文；打开菜单时隐藏 Crepe 浮动格式工具栏，避免两个操作面板重叠。
- 添加／编辑链接使用选区附近的非模态浮层，宽度 380 px，窄窗口保留 8 px 外边距；没有遮罩、不设背景 inert。顶部输入网址／路径／文件名，下面列出同级文件，使用中性选中行和文件图标；方向键与 Enter 选择文件，输入框旁的应用按钮提交手填地址。Esc、关闭按钮和点击外部取消；读目录失败、无匹配及未保存提示留在浮层内。靠近底边时向上展开，长列表内部滚动，编辑位置、模式或语言变化时关闭。

### 无法预览的轻量通知

- 打开二进制或非 UTF-8 文本时，使用 [src/preview-notice.ts](../src/preview-notice.ts) 的琥珀色胶囊提示，距窗口顶部 76 px、相对整个窗口水平居中。文字分别为“该文件格式暂不支持预览”和“该文件编码暂不支持预览”，不显示原始错误或完整路径。
- 使用 `ui-theme.css` 的 `--warning-soft*` / `--warning-icon-*` 状态色适配浅色、深色和系统主题；层级使用 `--z-popup`，无背景遮罩、不设置 `inert`、不抢占焦点，文档与文件树可继续操作。
- 默认 4 秒后消失；鼠标悬停或焦点进入通知时暂停计时，离开后重新计时。关闭按钮或 Esc 可关闭；连续失败复用一条通知并重新计时，已过期的预览读取不弹出通知。文字通过 `role="status"` 温和播报，随语言切换更新。
- 未找到文件、无权限等读取失败继续使用带具体原因的错误弹窗；未知扩展名的有效 UTF-8 文本仍可打开。

### 需要确认或查看详情的弹窗

应用内确认、警告、错误与消息统一使用 [src/dialogs.ts](../src/dialogs.ts)，生命周期使用 [src/modal.ts](../src/modal.ts)。设置、关于、文件命名、图片预览也使用同一焦点机制。原生文件选择器只用于打开文件和保存路径。

- 禁止为警告或确认调用系统 `ask` / `message`、`window.alert` / `window.confirm`，也不调用声音、震动或摇晃动画。
- 弹窗居中、遮罩为中性黑色半透明；卡片限制在视口内。标题左上、关闭按钮右上；内容左对齐，长内容在内部滚动。
- 普通确认默认宽度 620 px；文件命名 420 px；关于 440 px；设置 880 px。窄窗口保留 12 px 外边距，正文与按钮不超出窗口。
- 打开时背景设为 `inert`，Tab / Shift+Tab 在当前弹窗内循环；Esc、关闭按钮和遮罩点击执行取消。关闭后恢复原焦点；嵌套弹窗优先处理最上层。
- 危险确认初始焦点放在“取消”；Enter 不可因打开弹窗而自动批准删除。并发消息排队显示，避免覆盖待回答的确认。
- 文案使用操作名称及真实结果；不可使用“是/否”让用户猜测后果。用户内容使用 `textContent`，不插入 HTML。

### 删除确认

- 左上“删除文件”，正文说明目标名称，以及“移入系统回收站，可在回收站中恢复”。文件夹采用相同语义；失败通过应用内消息提示，不回退到永久删除，不显示系统删除确认或进度窗口。
- 显示待删除文件数；删除目录时统计其子文件。显示引用链接总数、来源文档数及可点击的来源列表。点击来源会取消本次删除并在新标签页打开来源文档。
- 来源统计由 [src-tauri/src/delete_info.rs](../src-tauri/src/delete_info.rs) 在后台线程读取磁盘完成，支持 Markdown 链接、图片、引用式链接和 wiki 链接，不把代码示例计为链接。不包含未保存文本、HTML 原始链接或工作区外文档。
- 扫描限制为 20,000 个目录项、单文档 2 MiB、合计 32 MiB，来源列表最多 200 项；达到限制或读取失败时明确显示未完成状态，不能用“0 个”冒充完整结果。读取待删除目标失败时禁用删除按钮。
- 左下为“不再询问”，右下为“取消”与红色“删除”。仅移入回收站成功后持久化 `confirm_delete = false`；取消、Esc、遮罩关闭或移入失败不会保存勾选。
- 不再询问仅作用于删除确认，不影响未保存修改提示。用户可在“设置 → 常规 → 删除文件前询问”恢复确认。

## 布局与状态

左侧功能栏自上而下为侧栏开关、文件、大纲、搜索；设置与关于位于底部，设置使用齿轮图标。实际设置采用 A 的左侧分类结构，固定标题与保存提示，右侧控件独立滚动；窄窗口改为顶部分类。原 A／B／C 与 A＋C 组合设计稿保存在 [HTML 预览入口](../output/settings-previews/index.html)，作为候选历史参考。

设置顶部带跨分类搜索，分类显示图标、页标题与简短说明。搜索结果标注分类／分组，点击后聚焦并突出对应控件；支持名称、配置键名、多关键词和扩展名，空结果给出明确提示。Esc 先清除搜索，重开面板重置查询。更新页沿用 A 预览的版本卡片：更新图标、真实版本、GitHub Releases 来源和检查按钮；下方用开关及说明展示自动检查偏好。检查中禁用重复操作，结果或错误直接显示在卡片中，不覆盖搜索或重置开关。

“编辑器 → 字体”提供“预览当前文档”：清除设置卡片背景，遮罩降至 2.5% 黑色，仅保留左上角不透明的字体控件，直接观察当前文档。字体和字号输入时即时应用并保存；背景文档继续保持 inert，防止误编辑。点击“返回设置”、Esc 或空白遮罩恢复完整面板；再次 Esc 关闭。窄窗口将控件放在底部，最高占 52% 窗口高度并可滚动，留出上方正文空间。关闭或语言重建会清除预览状态，不新增持久化透明度设置。

Markdown 的 H1～H6 字号依次为正文的 1.875、1.5、1.25、1.0625、1、0.9375 倍；正文为 16px 时对应 30、24、20、17、16、15px。编辑器标题行高为 1.4，导出使用相同字号比例，标题随正文字号缩放。

- 主窗口的标题栏放常用操作；文件树与大纲共用左侧空间，文档区域随窗口宽度伸缩。侧栏收起后内容占满剩余空间。
- 标签栏仅占文档区域顶部；多个标签会随空间缩窄，悬停时显示完整文件名。标题栏右侧固定显示新建标签页和标签页列表按钮，列表可切换、堆叠、收藏和关闭标签页；列表菜单按内容收紧宽度，长文件名超过宽度上限时省略显示。
- 标签关闭按钮在浅色、深色主题下始终可见；选中、悬停或键盘焦点进入标签时提高不透明度。文件名始终为关闭按钮预留空间，悬停时不移动文字。
- 文件树普通点击复用预览标签页，右键“在新标签页中打开”固定该文件的标签页。替换有未保存修改的预览时先请求确认。
- 右键打开独立标签页时立即显示标签，读取完成前显示“正在打开文件…”并隐藏编辑与保存、导出操作。加载中允许切换和关闭；完成时仅更新对应标签，不改变后续选择。
- 新标签页显示创建文件、打开文件和关闭标签页三个入口；创建文件后才进入空白编辑器。
- Windows 自定义标题栏的最小化、最大化/还原和关闭按钮始终位于顶部最右侧，不受标签栏显示或隐藏影响。
- 文件树以文件夹图标、层级缩进和细竖线表示目录关系；当前文档、悬停和键盘焦点要能区分。右键菜单的“删除”使用警示色，并在实际删除前确认。
- 文件树路径栏按路径段换行，分隔符与后面的名称同组；单个超长名称省略并保留完整路径提示，↑／◎／搜索不能被挤出侧栏。可返回的路径按钮按 Tab 顺序遍历，Enter／Space 进入后及目录刷新时保持焦点；当前位置不额外占用 Tab 顺序，焦点使用强调色描边。
- “在新窗口中打开”是同一进程内的单文档窗口：不显示文件树、大纲或标签栏，保留该文档需要的阅读与轻量编辑操作。
- 图片以容器宽度为上限等比例缩放。放大预览为只读遮罩，关闭时返回原焦点；滚轮缩放、拖动和关闭操作不改写文档。
- Markdown 渲染与 Code 模式的切换应保持阅读位置，避免在长文中意外跳回顶部。非 Markdown 文件直接使用 Code 模式，不显示“可切换回渲染”的状态。

## 交互检查

Markdown 表格保留浅色表头、细边框和圆角，列宽按内容自动分配，不强制等宽或为所有表格固定三列比例。单元格顶端对齐，内部段落去除首尾留白，以紧凑行距展示短分类与较长说明。

新增控件应有可理解的文本或可访问名称、可见焦点、禁用状态说明，并随界面语言更新。菜单、对话框和图片遮罩要支持 Esc 关闭；点击暗色背景关闭图片预览时不要触发正文编辑。内容样式与应用框架样式分开维护，优先复用现有 CSS 变量和组件状态。
