# 性能改进实施方案

方案依据：截至 2026-09-30，已对照当前源码、本地 Milkdown 7.22.1 和工作区未提交改动进行只读核对。尚未运行性能基线；以下收益均为预期。实施前须重新核对代码与未提交改动，并在同一机器、构建和测试数据上记录修改前基线。先消除已确认的重复工作，再由测量结果决定是否进行结构调整。

> 下文保留实施前的方案与验收标准。文末“本轮实施记录”说明实际改动、已验证内容和仍待测量的部分；方案中的预期收益不等于实测收益。

**1. 编辑后的全文处理：优先复用回调文本**

修改位置：[editor.ts](../src/editor.ts#L352)、[main.ts](../src/main.ts#L661)。

* 将 `markdownUpdated` 提供的 Markdown 传给主流程，同一份文本用于更新标签内容、脏状态和大纲，消除回调内两次 `readView()`。
* Code 模式同样只读取一次文本。
* 为延迟回调设计文档归属校验，覆盖标签切换、程序性替换内容和编辑器重建。
* 保存和切换标签目前已直接读取当前编辑器内容，修改时保留这一行为。关闭标签与退出应用目前根据 `tab.dirty` 判断是否提示；在确认前同步当前标签的脏状态，避免依赖尚未触发的延迟回调。
* `saveDoc()` 在等待异步写入后会将标签标为干净。若等待期间又发生编辑，写入完成后须根据最新编辑内容重新判断脏状态，并避免旧保存结果覆盖新内容。

大纲和统计先保留现有算法。若测量后仍有明显开销，先考虑合并刷新、标题列表未变时跳过 DOM 重建，再考虑事务级增量计算。统计目前使用纯文本，不能直接换成 Markdown 字符串而改变计数口径。

**验收：** 编辑回调不再额外序列化；快速输入后立即保存、切换、关闭均不丢内容且未保存提示正确；慢速写入期间继续编辑后，标签仍标为未保存；撤销回原内容后脏状态正确。

**2. 会话恢复：合并为一次读取**

修改位置：[main.ts](../src/main.ts#L1917)、[assets.rs](../src-tauri/src/assets.rs#L25)。

* 每个文件读取成功后直接建立标签，移除“完整读取验证，再完整读取建标签”的两轮流程。
* 每个文件独立处理失败，其余标签继续恢复。
* 恢复前保存原活动标签对应的路径或条目标识；过滤失效文件后按身份恢复，避免继续使用旧索引选错标签。
* 图片增加读取前大小检查，并使用最多读取“上限＋1 字节”的有界读取，避免文件增长或超大文件导致无界内存分配。

首轮保留顺序读取，便于独立验证收益。若大量标签仍明显影响交互，再引入“活动标签优先、其他标签激活时加载”。届时需要明确 `unloaded/loading/ready/error` 状态，并将图片类型与 `imageUrl` 是否存在解耦。

**验收：** 每个成功恢复的文件只发起一次内容读取；单文件失败不阻断恢复；活动标签和顺序正确。单次读取主要减少恢复过程的工作量，长期图片驻留内存仍需另行评估。

**3. 文件名搜索：先处理失效查询，再调整搜索范围**

修改位置：[workspace-sidebar.ts](../src/workspace-sidebar.ts#L337)、[workspace.rs](../src-tauri/src/workspace.rs#L80)；若修改命令注册，同步检查 [lib.rs](../src-tauri/src/lib.rs)。

* 输入变化时立即使旧查询失效，180 ms 防抖仅控制新查询何时启动。当前 token 在真正启动搜索时才更新，等待期间旧结果仍可能显示。
* 清空查询、关闭搜索、切换根目录时立即失效旧查询；过期错误也不再弹出。
* 先测量旧查询的实际遍历耗时、同时运行数和取消后的资源占用。若旧查询持续占用明显资源，再在 Rust 侧增加按窗口隔离的取消状态，并在目录循环和条目循环中检查；同时评估后台任务与每窗口单个可替换待执行查询的必要性。
* 若达到数量或遍历预算会造成用户可见的误判，返回“结果不完整”状态，并同步调整前端结果提示及多语言文案。

第一阶段先修正前端过期结果处理，沿用现有搜索范围。遵守忽略规则、排除生成目录属于产品行为变化，建议作为明确可见的选项另行设计；文件名索引放在取消机制仍无法满足需求之后评估。

**验收：** 快速输入、清空和换根目录后不显示过期结果或错误；若实施 Rust 侧取消，旧遍历应在下一检查点退出，并单独记录不可中断的文件系统调用造成的取消延迟。

**4. 图片工具栏：跳过选区变化引起的全文同步**

修改位置：[image-toolbar.ts](../src/image-toolbar.ts#L456)。

* 区分工具栏选区更新和图片属性同步：移动光标仍更新工具栏显示，但文档未变时跳过全文扫描。
* 对齐和标题仅在值变化时写入；宽度已有差异判断，继续保留。
* 首次挂载、图片加载完成、标签切换和必要的布局变化保留同步入口。
* 多张图片加载完成引起的同步请求按帧合并，避免每张图片都立即扫描全文。

当前函数会遍历整篇文档节点，再筛选图片，因此扫描成本也受非图片节点数量影响。首轮保留现有缩放与 CSS 语义；只有剩余开销显著时，再考虑局部同步或节点视图改造。

**验收：** 图片全部加载后，纯光标移动触发的全局图片扫描为零；缩放、对齐、标题、异步加载及 Markdown/HTML 图片显示保持正确。

**实施前的测量与取舍**

| 场景  | 建议样本                         | 主要指标                   |
| :-- | :--------------------------- | :--------------------- |
| 编辑  | 10 KB、500 KB、2 MB；少量/大量标题和图片 | 回调分项耗时、长任务、输入响应        |
| 恢复  | 1、20、50 个混合标签                | 可交互时间、恢复完成时间、读取次数、内存峰值 |
| 搜索  | 普通目录、生成文件多的目录、单个超大目录         | 查询耗时、扫描条目数、取消延迟、任务数量   |
| 图片  | 0、20、200 张图片                 | 全局扫描次数、同步耗时、布局正确性      |

固定机器、构建和数据，热缓存场景建议至少重复 30 次，记录中位数和 P95；冷启动单独记录。先以“重复工作确实消除、正确性回归通过”为硬性验收，再根据基线设定耗时目标，不预设未经测量的提升百分比。

建议先做文本复用和单次恢复，再依据测量安排图片同步与搜索取消。各项改动应能独立回退；增量统计、惰性标签、文件索引和图片传输协议调整留作后续候选。Windows 验证结果需与 macOS/Linux 的路径、文件系统及 WebView 回归结果分开记录。

## 本轮实施记录（2026-09-30）

| 项目 | 已实施的第一阶段 | 尚未实施及原因 |
| --- | --- | --- |
| 编辑后的全文处理 | Milkdown 回调把已序列化的 Markdown 传入主流程；Code 模式每次变更只取一次文本。延迟回调核对当前 ProseMirror 文档，切换、关闭及退出前同步当前编辑器内容与脏状态。保存期间继续编辑时，写入完成后按最新内容重算脏状态。 | 大纲增量计算及统计重构：尚无耗时证据。 |
| 会话恢复与图片读取 | 每个标签仅调用一次内容读取；单个读取失败不会中止其余标签；按原保存索引对应的标签身份恢复焦点。Rust 图片读取先查元数据，再最多读入上限加 1 字节，仍执行读后大小检查。 | 惰性标签加载和图片驻留内存优化：需先测大量标签的交互延迟与内存。 |
| 文件名搜索 | 输入、清空、关闭搜索和切换目录时立即使旧查询失效；延迟启动新查询，过期结果和错误不再呈现；切换目录读取期间不启动旧目录搜索。 | Rust 侧遍历取消、搜索范围和文件索引：需测旧任务的实际资源占用。 |
| 图片工具栏 | 纯选区事务只更新工具栏，不做全文图片扫描；图片属性有变化才写入 DOM；多张图片的加载回调按动画帧合并同步。 | 局部扫描或节点视图：需测剩余扫描成本并验证复杂图片文档。 |

**自动验证：** `pnpm build` 通过（含 `tsc --noEmit` 和 Vite 生产构建）；Windows 环境中 `cargo test --manifest-path src-tauri/Cargo.toml --offline` 通过 23 项，其中新增超大图片拒绝测试。仓库原有 Rust 文件有格式差异，因此全仓 `cargo fmt --check` 未通过；本轮未批量重排无关文件。

**尚无运行时收益数字：** 本轮未取得改动前、改动后的同条件 UI 性能基线。源码路径可确认每次 Milkdown 更新不再额外调用两次 `readView()`，恢复流程每个成功文件由两次读取变为一次，纯选区事务不再发起图片全文扫描；这些是工作量减少的代码事实，不是毫秒级加速结论。请按上表样本补测中位数、P95、内存及搜索任务数，再决定是否实施第二阶段。

**仍需人工回归：** 快速输入后立刻保存、切换、关闭或退出；保存写入未完成时继续编辑；会话含不可读文件时的顺序和活动标签；快速搜索、清空和切换根目录；多图加载后缩放、对齐、标题与 HTML 图片的显示。macOS/Linux 尚未验证。

## 测量与回归追加（2026-10-01）

上述“尚无运行时收益数字”描述 2026-09-30 的实施时点。同机 30 次热缓存对照现已完成，分项耗时、读取/扫描次数、内存抽样及适用范围见 [性能基线](performance-baseline.md) 和 [原始结果](performance-baseline.json)。图片选区事务不再扫描全文，编辑回调额外序列化由两次变为零，恢复内容读取由两轮合并为一轮。Rust 搜索遍历未改动；没有声称后端搜索加速或已实现取消。

测量时发现标题 ID 的非历史事务会更换文档对象，使严格对象身份过滤误丢标题编辑。现以文档代次判断归属；真实编辑器的标题编辑、快速替换文档和重建后的旧回调检查通过。慢速保存、过期搜索与异步 Markdown/HTML 图片检查通过；Windows 原生交互的已完成记录与剩余事项分别见 [开发说明](development.md) 和 [TODO](../TODO.md)。
